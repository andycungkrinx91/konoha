# Helm Chart Scaffolding

Comprehensive guidance for creating, organizing, and managing Helm charts for packaging, templating, and deploying Kubernetes applications within Anbu DevOps workflows.

## Role & Purpose in Anbu

As part of Anbu's DevOps and Infrastructure capabilities, Helm chart scaffolding provides standardized packaging for containerized applications, enabling predictable deployments across development, staging, and production Kubernetes clusters.

### When to Use This Skill

- Creating new production-ready Helm charts from scratch.
- Packaging containerized backend microservices and web applications for distribution.
- Managing multi-environment deployments (`values-dev.yaml`, `values-prod.yaml`).
- Implementing reusable templating patterns (`_helpers.tpl`) and resource isolation.
- Enforcing Kubernetes security best practices (non-root execution, dropped capabilities, read-only root filesystems).
- Linting, rendering, and validating Helm charts in CI/CD pipelines.

## Standard Chart Directory Structure

```text
my-app/
├── Chart.yaml              # Chart metadata (API v2, version, appVersion, dependencies)
├── Chart.lock              # Dependency lock file (generated by helm dependency update)
├── values.yaml             # Default configuration values (well-commented)
├── values.schema.json      # JSON schema for values validation
├── .helmignore             # Patterns to ignore when packaging
├── README.md               # Chart documentation and values reference
├── LICENSE                 # Chart license
├── charts/                 # Bundled chart dependencies (e.g. postgresql, redis)
├── crds/                   # Custom Resource Definitions (installed prior to templates)
├── templates/              # Kubernetes manifest templates
│   ├── NOTES.txt          # Post-installation instructions rendered to CLI
│   ├── _helpers.tpl       # Named template helpers and label definitions
│   ├── deployment.yaml    # Core workload deployment
│   ├── service.yaml       # Service endpoints (ClusterIP / NodePort / LoadBalancer)
│   ├── ingress.yaml       # Ingress routing and TLS configuration
│   ├── configmap.yaml     # Environment configuration
│   ├── secret.yaml        # Sensitive credential mounts (or ExternalSecrets)
│   ├── serviceaccount.yaml# Dedicated RBAC identity
│   ├── hpa.yaml           # Horizontal Pod Autoscaler
│   ├── pdb.yaml           # Pod Disruption Budget
│   ├── networkpolicy.yaml # Ingress/egress network isolation
│   └── tests/             # Helm test hooks
│       └── test-connection.yaml
└── files/                  # Non-templated raw configuration files
    └── config.json
```

## Chart.yaml Specification (Helm 3+)

Every chart requires a root `Chart.yaml` defining metadata and dependencies:

```yaml
apiVersion: v2
name: my-app
description: Production-grade Helm chart for Anbu microservice
type: application # "application" or "library"
version: 1.0.0    # Chart SemVer (bump on packaging changes)
appVersion: "2.1.0" # Upstream container application version
kubeVersion: ">=1.26.0"

keywords:
  - backend
  - microservice
  - kubernetes
  - helm

sources:
  - https://github.com/my-org/my-app

maintainers:
  - name: Anbu DevOps Team
    email: devops@example.com

dependencies:
  - name: postgresql
    version: "12.1.0"
    repository: "https://charts.bitnami.com/bitnami"
    condition: postgresql.enabled
    alias: db
```

## Core Template Helper Patterns (`_helpers.tpl`)

Template helpers centralize naming, labels, and selector logic to ensure consistent metadata across all generated resources:

```yaml
{{/*
Expand the name of the chart.
*/}}
{{- define "my-app.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 | trimSuffix "-" }}
{{- end }}

{{/*
Create a default fully qualified app name.
*/}}
{{- define "my-app.fullname" -}}
{{- if .Values.fullnameOverride }}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- $name := default .Chart.Name .Values.nameOverride }}
{{- if contains $name .Release.Name }}
{{- .Release.Name | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- printf "%s-%s" .Release.Name $name | trunc 63 | trimSuffix "-" }}
{{- end }}
{{- end }}
{{- end }}

{{/*
Common labels applied to all resources.
*/}}
{{- define "my-app.labels" -}}
helm.sh/chart: {{ include "my-app.chart" . }}
{{ include "my-app.selectorLabels" . }}
{{- if .Chart.AppVersion }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
{{- end }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}

{{/*
Selector labels used in deployments and services.
*/}}
{{- define "my-app.selectorLabels" -}}
app.kubernetes.io/name: {{ include "my-app.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end }}

{{/*
Create chart name and version as used by the chart label.
*/}}
{{- define "my-app.chart" -}}
{{- printf "%s-%s" .Chart.Name .Chart.Version | replace "+" "_" | trunc 63 | trimSuffix "-" }}
{{- end }}
```

## Standard Values Configuration (`values.yaml`)

```yaml
# Global settings
global:
  imageRegistry: docker.io
  imagePullSecrets: []

# Workload replica count
replicaCount: 2

# Container image
image:
  registry: docker.io
  repository: my-org/my-app
  tag: "" # Defaults to .Chart.AppVersion
  pullPolicy: IfNotPresent

# Security context (Least Privilege Invariant)
podSecurityContext:
  runAsNonRoot: true
  runAsUser: 10001
  runAsGroup: 10001
  fsGroup: 10001
  seccompProfile:
    type: RuntimeDefault

securityContext:
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities:
    drop:
      - ALL

# Service definition
service:
  type: ClusterIP
  port: 80
  targetPort: 8080

# Ingress
ingress:
  enabled: true
  className: nginx
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
  hosts:
    - host: app.example.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: app-tls-cert
      hosts:
        - app.example.com

# Compute resources
resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 100m
    memory: 128Mi

# Probes
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 15
  periodSeconds: 10
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5

# Autoscaling
autoscaling:
  enabled: false
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 80
```

## Validation & Testing SOP

Before deploying or committing any Helm chart, execute the following verification pipeline:

### 1. Linting & Syntax Check
```bash
helm lint ./my-app
```

### 2. Dry-Run Template Rendering
Verify template substitution without touching the cluster:
```bash
helm template test-release ./my-app --debug
```

### 3. Dry-Run Installation
Verify cluster validation schema against the active Kubernetes API:
```bash
helm install test-release ./my-app --dry-run --debug
```

### 4. Automated Validation Script
Use the integrated chart validator:
```bash
./scripts/validate-chart.sh ./my-app
```

## Best Practices & Guardrails

1. **Semantic Versioning**: Chart `version` and `appVersion` must adhere to SemVer. Bump `version` on template/value changes; bump `appVersion` on application binary changes.
2. **Commented Defaults**: Every variable in `values.yaml` must have an explanatory comment indicating its type and default behavior.
3. **Template Helpers**: Never hardcode resource names or label selectors; always use `_helpers.tpl` functions.
4. **Security Context**: Enforce `runAsNonRoot: true`, `readOnlyRootFilesystem: true`, and `drop: [ALL]` capabilities.
5. **Deterministic Dependencies**: Always run `helm dependency update` to maintain a committed `Chart.lock` file.
6. **Zero Hardcoded Secrets**: Never put raw tokens, passwords, or private keys in `values.yaml`. Use external secret stores (ExternalSecrets, Vault) or inject via sealed secrets.
