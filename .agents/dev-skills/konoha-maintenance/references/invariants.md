# 🍃 Konoha Cardinal Maintenance Invariants (v2.2.24)

Loaded on demand from `konoha`. Each rule already shipped as a bug once; the code reference in each rule is the guard.

1. **Tool Boundaries & Global-Only Configs**:
   - Repository code search: ALWAYS use the native code intelligence tools (`code_search`, `code_symbol`, `code_impact`).
   - Skill lookup: ALWAYS use Konoha MCP (`konoha.find_skill`, `konoha.get_skill`).
   - Bounded file I/O: ALWAYS use Konoha bounded tools (`read_file_range`, `read_file_head`, `token_efficient_grep`).
   - Shell commands: ALWAYS prefix with RTK (`rtk <command>`).
   - Global-Only & Append-Only Client Configs: Never write `.omp`, `.codex`, `.cursor`, `.claude`, `.agents`, or `.gitignore` rules (such as `/PLAN.md` or `.omp/.`) into user project directories; all client configs live under user home (`~/.omp`, `~/.codex`, `~/.cursor`, `~/.config/git/ignore`, etc.) and use automatic date-stamped backups (`~/.konoha/backups/configs/<client>/<scope>/`) + syntax-aware append-only merging (`src/config_backup_manager.js`, `src/config_merger.js`) with ownership tracking (`~/.konoha/backups/ownership_manifest.json`). Konoha never deletes external `agents/` or `conversations/` directories.
   - Ownership-Aware Rsync-Like Global Skill Sync & Targeted Diff-and-Patch (`src/global_skill_sync.js`): all 17 canonical Konoha skills, their references (including the cross-framework Motion references `motion-nextjs`, `motion-nuxt`, `motion-svelte`, `motion-angular`, `framer-motion-animator` under `jonin-skill`), and `SOUL.md` are synchronized across the ten global skill directories of the eight supported clients (`~/.agents/skills`, `~/.gemini/antigravity-cli/skills`, `~/.gemini/skills`, `~/.cursor/skills`, `~/.claude/skills`, `~/.config/opencode/skills`, `~/.commandcode/skills`, `~/.codex/skills`, `~/.pi/agent/skills`, `~/.omp/agent/skills`). The source is `src/templates/skills`; `~/.agents/skills` is a deployed mirror, while this repository tracks its own `.agents/skills/` and pins it byte-identical to the templates. Fresh installs skip pre-existing user files (`--ignore-existing`), upgrades apply targeted line diff-and-patch updates (`computeLineDiffPatch` / `applyTargetedTextPatch`) while preserving user customizations, and a file recorded as `created_by_konoha` with no user keys is replaced wholesale instead of being left stale.
   - No Filesystem Mirrors: Konoha does not maintain filesystem mirrors of client skills; synchronization is targeted line diff-and-patch in place. Outside this repository no tracked copy of a skill exists: deployed copies live under the user's home. The one tracked duplicate is this repo's `.agents/skills/`, held byte-identical to `src/templates/skills` by `tests/test_skill_tree_parity.js`.
   - Scoped Execution & External Skill RAG Integration: Hooks and tool blockers activate only inside Konoha-managed contexts (`/konoha <prompt>` or `/<subagent-name> <prompt>`). External global and project-level skills across all 8 harnesses are indexed in-place into the existing SQLite Project Knowledge RAG (`~/.konoha/konoha.db`) with strict project isolation (`isPathVisible`) so project skills never leak across workspaces.
   - Project Skills Outrank the Index: `getSkillReadRoots()` (`src/mcp/skills_common.js`) resolves the project's own tree — `.agents/skills` and the eighteen `PROJECT_SKILL_SUBDIRS` — ahead of client mirrors, and `findSkill`/`listSkills` merge those rows with the database. Never make a project migrate before its skills are usable, and never let a Konoha skill shadow a project skill of the same name. `tests/test_project_skills_dual_source.js` is the guard.
   - Extension Isolation: The obsolete `andycungkrinx91.konoha-bridge-master-universal` extension directory is eliminated; all IDEs use direct MCP configuration.
2. **Quality & Security Delivery Gate**:
   - Shipped code must pass `rtk npx aislop scan --changes` with score **100/100 Healthy**, 0 errors, and 0 warnings.
   - Final Kage review requires `confidence >= 98%`, `ai_slop_clean: true`, and zero security findings.
3. **Source File Line Limit**: Keep all `.js`, `.py`, and `.svelte` source files strictly under 700 lines (`scripts/lint.js`).
4. **Draw.io Zero Collision Rule**: Never introduce overlapping cells or bounding-box collisions in Draw.io diagram pages (`tests/test_diagram_sync.js`).
5. **Single-Source Version Synchronization**: Keep all 23 managed repository targets strictly synchronized via `scripts/bump_version.js`. The manifest is the source of truth — read the count from `rtk node scripts/bump_version.js --check`, never hardcode it in prose or code. `src/templates/skills/konoha/SKILL.md` is not a managed target, so this skill's own title is edited by hand.
6. **Release Governance**: When maintaining or updating Konoha on branch `master`, ensure all discovered tests pass before release commits.
7. **Token Savings Flow Logic Preservation Invariant**: Never modify or disrupt the token savings telemetry flow logic. In `src/tools_savings_logger.js`, baseline bytes for `find_skill` / `find_skills` are dynamically computed from the actual `SUM(byte_size)` of retrieved skill candidates in SQLite FTS5 matching, authentically reflecting 83%–98% context savings.
8. **Schema Version Is Not the App Version**: `src/db_schema.js` owns `CURRENT_SCHEMA_VERSION` (9 today), the shipped `PRAGMA user_version` write, and the canonical 46 raw / 34 declared table list. Never reintroduce a version-derived schema constant — a `TARGET_SCHEMA_VERSION = 2218` once shipped and was removed in 2.2.18. `konoha doctor` reports `schema 9` and `app 2.2.24` separately and warns on drift; `tests/test_schema_migrations_and_lifecycle.js` fails if a second writer appears or the table count moves.
9. **Red-Skill Isolation Fails Closed**: `src/skill_authorization.js` classifies a skill by exact canonical name → `RED_SKILL_ROOT_PATTERN` (`^(?:akatsuki-skill)(?:[-_/@]|$)`) → legacy pattern → tags, and `src/mcp/skills_retrieval.js` resolves the row before authorizing it. Lab databases are rejected when they alias the main DB (same path, symlink, dangling symlink, hardlink), and any `stat` error other than `ENOENT`/`ENOTDIR` raises `LAB_DB_ISOLATION_VIOLATION` (`src/db.js`). Never widen those predicates "to be tolerant": this gate is what stops offensive tooling loading outside the sandbox.
10. **Cyber Pack Is Opt-In, Never Bundled**: the pack is downloaded only via `konoha akatsuki cyber-pack install --confirm`, sha256-verified, extracted under `~/.konoha/akatsuki-lab/cyber-pack/`, and indexed as `akatsuki-skill` references. `src/cyber_pack.js#remove` must keep using the deduped union of `bin/lib/paths.js#DEFAULT_SKILLS_DIRS` and `src/global_skill_sync.js#getGlobalHarnessSkillTargets`; the two lists still differ (the search list keeps the legacy `~/.opencode/skills`), and hardcoding either one is the bug that left copies behind.
11. **Migration Runs In-Process**: every caller awaits `runMigration({...})` from `src/migrate` — `bin/lib/install_lifecycle.js`, `bin/lib/runtime_lifecycle.js`, `bin/commands/migrate.js`, `bin/commands/upgrade.js`, `bin/commands/init_migration.js`, `bin/commands/doctor_services.js`, `src/skill_manager.js`, `src/web/controllers/skills_controller.js`. Never restore `spawnSync(process.execPath, [...migrate.js...])`: it hid every failure behind `status !== 0`. Success returns `{ ok: true, indexed, deferredSkills, dbPath }`; incomplete required skills return `{ ok: false, reason: 'required_skills_missing', missingRequired, remainingLegacy }`. Only `main()` exits the process.
12. **Time Budgets Come From Config**: `bin/lib/config_defaults.js` holds the shipped defaults as code (70 keys, including `migrate_time_budget_seconds` 900, `install_build_migrate_timeout_ms` 900000, and the `mcp_orphan_parent_poll_ms` / `mcp_stdio_idle_timeout_ms` / `mcp_daemon_superseded_poll_ms` orphan-guard polls) so an upgrade never rewrites the user's `~/.konoha/config.json`; `bin/lib/paths.js` derives `MIGRATION_TIMEOUT_MS` / `INSTALL_BUILD_MIGRATE_TIMEOUT_MS` from them. No `timeout: 900000` literal may reappear on the install path (`tests/test_config_centralization.js`, `tests/test_upgrade_timeout_budgets.js`).
13. **Mirrored Modules Load Config Through `src/config_access.js`**: `copyRuntimeConfigFiles` mirrors top-level `src/*.js` flat into `~/.konoha/`, so `require('../bin/lib/paths')` escapes to `~/bin/lib/paths` at runtime. Any `src/` module that may execute from the mirror must go through `config_access`, which tries `../bin/lib`, `./bin/lib`, `../../bin/lib`.
14. **Upgrade Success Requires PATH Agreement**: `konoha upgrade` runs the PATH-resolved `konoha --version` and compares it with the installed package (`bin/lib/upgrade_verify.js`). A missing binary, a rename, or output without a version line exits `1`. Never restore the old "located package root equals itself" comparison, which printed success while `konoha version` reported the previous release.
15. **No Install Scripts**: `postinstall` is deleted (npm aborts stock installs with `EALLOWSCRIPTS`). The supported flow is `npm install -g konoha-mcp` → `konoha init --yes` or `konoha upgrade`. `tests/test_postinstall_contract.js` no longer exists — do not cite or recreate it.
16. **The Token Governor Bounds Konoha's Own Graph, Not the Harness**: `src/mcp/langgraph/token_guard.js` accepts `ALLOWED_CEILINGS = [8192, 16384, 32768, 65536]`, defaults to 8192, and rounds invalid input up to the nearest allowed value. It clamps what Konoha hands the model *inside its internal LangGraph*. It does not budget harness model context. Never cite `8192` as a whole-session token ceiling.
17. **Two Databases, No Cross-Joins**: app data lives in `~/.konoha/konoha.db` (`src/db.js`); Akatsuki lab data lives in `~/.konoha/akatsuki-lab/lab.db` via `openLabDb()` (`src/workflow/akatsuki/lab_db.js`). A lab path handed to the main opener throws `LAB_DB_ISOLATION_VIOLATION`; `kali_tools` is created only by the lab opener, and no SQL may join the two databases — join in application code. Guards: `tests/test_akatsuki_lab_isolation_section_i.js`, `tests/test_akatsuki_skill_authz_db_isolation.js`.
18. **First-Run Login Opens on Set-New-Password**: while `GET /api/v1/auth/status` returns `is_bootstrap: true`, the web UI renders the setup form (`data-testid="first-run-setup-form"`) from `authState.isBootstrap`; never branch on a hardcoded `konohagakure` comparison. The 403 `requires_password_change` gate in `src/web_server.js` and the bootstrap password value in `src/auth.js` stay unchanged. Guard: `tests/e2e/login_default_password_redirect.spec.js`.
19. **A Server Nobody Owns Must Exit**: `src/mcp_orphan_guard.js` gives both long-lived entry points a self-terminating path. `startStdioOrphanGuard` polls `process.ppid === 1` every `mcp_orphan_parent_poll_ms` (30 s; `KONOHA_MCP_ORPHAN_POLL_MS` is a test seam, not user config) and exits when the spawning client died, so a stdio server orphaned by a short-lived launcher does not hold the bridge port or the database; `noteActivity()` on every `readline` line feeds a `mcp_stdio_idle_timeout_ms` (4 h; `KONOHA_MCP_STDIO_IDLE_MS`, same seam) idle budget, which is the only exit Windows has because Windows does not reparent children and `ppid` never becomes 1 there. `startDaemonOrphanGuard` claims `bridge.pid` and exits when a newer live daemon takes it over. Never remove the guard to "simplify startup": stdin EOF is not a reliable exit signal (a launcher that exits tears down its own pipe), so the poll is the only path that survives a reparent. Guards: `tests/test_mcp_orphan_guard.js`.
20. **The Web UI Starts Only by Hand**: `konoha ui` exposes exactly `start` (foreground, blocking) and `build`. Nothing auto-starts it — not `init`, not `upgrade`, not the MCP stdio bootstrap. A second `konoha ui start` on a port that is already listening exits 1 with `already running`; `assertSingleInstance` probes the port before binding. Guard: `tests/test_ui_manual_only.js`.

21. **A Delivery Verdict Needs All Three Local Cross-Platform CI Environments**: cross-platform end-to-end verification is mandatory, never optional. A change counts as done only after Linux, Windows, and macOS all pass — a single-OS green is not a verdict. Exercise all 3 local cross-platform CI test environments before handoff: (1) **Linux**: Debian clean-room `pnpm test:sandbox [-- --shard=I/8]` + Ubuntu `act` `pnpm ci:act` / `pnpm ci:act:shard` (`act -j checks` / `act -j test --matrix os:ubuntu-latest --matrix shard:<N>`, `.actrc` pins `catthehacker/ubuntu:act-latest`); (2) **Windows**: `docker/windows-vm/oem/run-ci.cmd [-Shard I/N]` / `retest.cmd` inside `dockur/windows` (`scripts/windows-ci.ps1`; the guest runs the full suite in one pass by default — CI's shards parallelize 16 separate runners, so use `-Shard` to narrow one failure, not to reproduce the matrix); (3) **macOS**: `KONOHA_SANDBOX_RUNTIME=container pnpm test:sandbox [-- --shard=I/8]` via Apple `container`, plus native `macos-latest` CI (or the Linux symlinked-`HOME` proxy for `/var` → `/private/var` and APFS path checks in `docs/CI.md`). `.github/workflows/cross-platform.yml` also runs on push, PR, tag, manual dispatch, and nightly at 02:00 UTC.

22. **No Dynamic Execution, Anywhere in the Runtime**: `src/`, `bin/`, and `scripts/` contain no `eval(`, no `new Function(`, no `Function('…')`, and no `node:vm` code generation. The generated guardrail hooks (`src/mcp_clients/command_code.js`, `src/mcp_clients/claude_code_hooks.js`, `src/pi_blocker_template.js`) embed `buildGuardrailCheckerSource()` verbatim as `const checkCommandGuardrails = function checkCommandGuardrails(command) {...}` — never wrap it in `new Function(source)()` and never `JSON.stringify` it into a string. `tests/test_no_dynamic_execution.js` scans every runtime file, then executes the generated hooks to prove deny/block/allow/unmanaged still behave.
23. **`lodash` Must Never Return (`patches/xlsx-populate@1.21.0.patch`)**: `xlsx-populate@1.21.0` is the only thing that ever pulled it, and its `template()` compiles strings with `Function`. The patch replaces all 19 `require("lodash")` sites with `lib/lodash-lite.js` (27 helpers, lodash-4 semantics) and deletes `browser/` (13.9 MiB webpack bundle, 52 `Function(` occurrences) plus `examples/` and the `browser` manifest field. Konoha resolves `main: lib/XlsxPopulate.js` only. Regenerating the patch from a fresh package loses the shim — `tests/test_xlsx_populate_lodash_lite.js` (74 semantics + XLSX round-trip) and `tests/test_dependency_posture.js` fail if it does.
24. **Patched and Bundled Dependencies Are Pinned Exactly**: `xlsx-populate`, `pptxgenjs`, `cfb`, `docx`, `playwright`, and `hash-wasm` carry exact versions (no `^`/`~`), and `.github/workflows/publish.yml` installs with `--frozen-lockfile`. A caret on a patched or bundled package lets the lockfile and the published tarball disagree about which bytes shipped. `tests/test_dependency_posture.js` enforces both.
25. **Images Enter the Presentation Engine as Buffers, Never Paths**: `pptxgenjs` turns `addImage({ path })` into `fs.readFileSync` and `{ path: 'http…' }` into an HTTPS GET. `src/workflow/tokubetsu-scribe/doc_engine_presentation.js` exposes `addInlineImage(slide, buffer)`, which requires an in-memory PNG (magic-byte checked) and emits a base64 data URI; it holds the file's only `addImage` call site. `tests/test_document_engine_security.js` fails if a second call site or a `path:` key appears.
26. **Socket Suppressions Are Narrowed, Never Widened**: `socket.yml` keeps `envVars`, `urlStrings`, `networkAccess`, `gptSecurity`, `gptAnomaly`, and `newAuthor` suppressed because those describe Konoha's documented contract. It must **not** suppress `usesEval` (nothing dynamic executes, and no patched package ships a browser bundle) and must **not** list `pnpm-lock.yaml` or `patches/**` in `projectIgnorePaths` (dependency and patch changes are exactly what needs auditing). Suppressing an alert is not a fix; it is a written claim that the capability is intended, and `tests/test_dependency_audit.js` asserts the claim stays honest. The configuration governs the optional Socket.dev integration only — the mandatory gate is the local `pnpm audit` over the root and `apps/web` workspaces.
27. **The Per-Turn Prefix Is a Budget, Not a Dumping Ground**: what Konoha injects into a harness prompt is paid on *every* request, so it is governed like any other contract. `buildManagedContract` (`src/agent_contract.js`) removes **every** `KONOHA-CONTRACT-START`…`KONOHA-CONTRACT-END` span before writing the fresh block — splicing only the first pair left a second block forever, made redeploy a permanent no-op, and put two contract versions in one file. `buildOmpWorkflowAddendum` (`src/omp_manager.js`) carries *rules only*: framework scaffolding commands and scan-scoping procedure live in `jonin-skill` / `konoha` references, which load on demand. Only one user-level context file is injected per harness (`~/.omp/agent/AGENTS.md` shadows `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md`, `~/.config/opencode/AGENTS.md`, `~/.agents/AGENTS.md` for OMP), and `~/.omp/AGENTS.md` is not a context file at all — the native user path is `~/.omp/agent/AGENTS.md`. Guards: `tests/test_lightweight_contracts.js` (addendum ≤ 4200 B, managed contract ≤ 5200 B, second deploy `changed: false`) and the duplicate-block regression in `tests/test_omp_manager.js`. Never quote a cache-hit rate from `tool_calls`: its `input_tokens` / `output_tokens` / `cached_tokens` columns exist in `src/db_schema.js` but nothing on the MCP path writes them.

28. **A Path Is Not Whitespace-Delimited**: any code that turns a string into a command must survive an executable path containing spaces, because that is the Windows default (`C:\Program Files\nodejs\node.exe`) rather than an edge case. `_parseCommandSpec` (`src/code_intel/lsp_manager.js`) accepted only a whitespace-split string and therefore resolved `C:\Program`, so every LSP leg reported `server binary missing` on Windows while passing on Linux and macOS. The rule: take an **array** as the unambiguous form (element 0 verbatim), honour `"…"`/`'…'` quoting in the string form, and report an unquoted spaced path as a missing binary instead of silently resolving a prefix — a wrong-but-plausible command is worse than a refusal. `src/platform_utils.js#normalizeCommand` already follows this shape; copy it rather than writing a new splitter.
29. **A Payload Gate Measures the Worst Client, and a Call Carried as Data Is Not Repeated in Prose**: `runSannin` output is capped by `tests/test_e2e_install_upgrade_reinstall.js`, and a cap that reads `detectActiveClient()` is not a gate — the same commit reported 2 951 bytes on one host and 3 315 on another, because OMP native `task(...)` is the longest spawn form of the ten. The loop now pins `server.ACTIVE_CLIENT` for each client, keeps the maximum, and names it in the failure. The other half is dedupe: `advisor_spawn_directive` exists to carry the advisor spawn call as a field, so interpolating the same string into `instructions` pays for it twice (~299 B per response on OMP). Point at the field instead. A field nothing reads is not "carried" — delete it: `buildAdvisorStartupDirective` built a markdown `directive` string no caller consumed, while `supported_native` is asserted per client by `tests/test_subagent_spawning_p0.js` and stays. Raising a cap is the last resort; if it moves, the new number is measured across every client and recorded in `docs/QA-TEST-CHECKLIST.md`.

30. **Never delete a mirror copy before its replacement exists**: replacing a flat `~/.konoha/<name>` copy with a symlink removed the copy first, and symlink creation needs elevation on Windows — so the install lost `~/.konoha/server.js` and `~/.konoha/mcp/`, both golden-seed sentinels, while `konoha init` still exited 0. Probe symlink support, stage the link, and swap only after it exists (`src/deploy_installer.js#replaceWithMirrorLink`, `tests/test_mirror_link_failure_safety.js`).
31. **A version bump must touch every version-bearing line the tests assert**: `bump_version.js` rewrote only `**Version of record: X**` in `docs/MANUAL.md`, while `tests/test_manual_book.js` asserts the `| Manual version | X |` table row, so a clean bump left the suite red. The managed `check()` now requires the table row, so a partial bump fails `--check` instead of the suite (`scripts/bump_version.js`, `tests/test_manual_book.js`).
32. **Semantic dedupe needs mean-centered vectors**: the Granite embedder rates two unrelated sentences at ~0.997 cosine and identical text at 1.0, so a fixed 0.90 threshold on raw vectors discards every valid item. Center the candidate set before comparing — unrelated pairs then fall to -0.46..0.41 (`src/mcp/chunin_knowledge.js#centerVectors`, `tests/test_chunin_knowledge.js`).
33. **Schema table-count pins are deliberate**: adding a table changes `RAW_TABLE_COUNT`/`DECLARED_TABLE_COUNT` in `tests/test_schema_traceability.js` and the phase-6 count in `tests/test_schema_migrations_and_lifecycle.js`, and every new table must appear in `docs/security/DATABASE-SCHEMA-AUDIT-2026-11-09.md`. Update all three together; never loosen the assertion.
34. **`node:sqlite` has no `.transaction()` helper**: the repo's `sqlite_driver` wrapper adds one, so code that may run against a raw `DatabaseSync` (tests, scripts) must use explicit `BEGIN IMMEDIATE`/`COMMIT` with a manual rollback.
35. **Generator dependencies must be declared, and in the right manifest key**: five `scripts/` generators require `@napi-rs/canvas`/`gifenc`; undeclared they fail with `MODULE_NOT_FOUND` on a clean checkout. The root `devDependencies` allowlist permits only `@playwright/test`, so artefact generators belong in `dependencies` and on that allowlist (`tests/test_manifest_invariants.js`).
