# 🍃 Konoha Code-Intel, Guardrail & Subagent Contracts (v2.2.23)

Loaded on demand from `konoha`. Each rule already shipped as a bug once; the code reference in each rule is the guard.

- **HF Cache Parity (`src/hf_cache_resolver.js`)**: `src/vector_pipeline.js` delegates HuggingFace Hub cache discovery and `KONOHA_SEMANTIC_SEARCH` availability checks to `src/hf_cache_resolver.js` (keeping both modules well under the 700-line limit).
- **Project-Only Konoha MCP Guardrail (`src/project_konoha_mcp_guardrail.js`, `src/guardrail_hitl.js`, `src/guardrail_exceptions.js`, `scripts/konoha_project_mcp_guard.js`)**: Active exclusively inside the Konoha repository (`isKonohaRepository`); rejects unrouted native file/search/shell/legacy-IPC (`prompt.md`, `delegate.md`, `delegated.md`, `result.md`) calls across all 8 harnesses unless routed through Konoha MCP and Konoha maintenance skills. A denial is a **branchable decision, not a dead end**: `GUARDRAIL_REMEDIATION` maps every denial code to a concrete fix, `--hitl` renders the menu (`block and try another way` / `accept with risk` + ≥8-char justification) on the controlling terminal — `/dev/tty`, or `CONIN$`/`CONOUT$` on Windows — when stdin is a pipe, and an accepted risk is stored as a code+tool-scoped entry with a TTL capped at one hour. Hooks stay non-interactive and fail-closed; `KONOHA_GUARD_NO_TTY=1` can only force a block. The exception store (`.konoha/guardrail-exceptions.json`, `.konoha/guardrail-audit.jsonl`) is itself an attack surface: a write to it from any tool path is denied with a non-acceptable code, and some denials (secret write, destructive shell, retired IPC/MCP, store write) cannot be accepted at all. Guards: `tests/test_project_konoha_mcp_guardrail.js` tests 9-15, including a real pty leg through `tests/helpers/pty_driver.py`.
- **16 Code-Intel Languages (`src/code_intel/capabilities.js`)**: Supports `javascript`, `typescript`, `python`, `go`, `rust`, `c`, `cpp`, `shell`, `sql`, `php`, `ruby`, `kotlin`, `swift`, `dart`, `elixir`, `zig` (Tree-sitter WASM + fallback + optional stdio LSP); `java`, `csharp`, and `lua` are explicitly excluded (`EXCLUDED_LANGUAGES`).
- **Fail-Closed Subagent Spawning, Turn-0 Idle `@advisor`, 100k Quota LangGraph Compaction & Live TODO Sync (`src/mcp/lazy_subagent.js`, `src/context_compaction.js`, `src/mcp/langgraph/checkpointer.js`, `src/mcp/todo_walkthrough_sync.js`, `src/workflow/kage-reviewer/advisor_monitor.js`, `src/context_budget.js`)**: Routes the 8 spawnable specialists (`kage`, `jonin`, `anbu`, `chunin`, `tokubetsu-jonin`, `genin`, `akatsuki`, `yamanaka`) via harness-native descriptors + `konoha run-agent` child processes, keeps `@advisor` idle from turn 0 (`<= 8,192 tokens` / `32,768 bytes` interrupt budget) to steer drifted agents, captures per-agent LangGraph SQLite checkpoints (`lg_checkpoints`, namespace `agent:<name>`) + compacts + auto-continues when reaching `agent_input_token_quota` (`100,000` default / `KONOHA_AGENT_INPUT_TOKEN_QUOTA`), and synchronizes full `client_todo_directive` (`native_payload`), `walkthrough_steps`, `TODO.md`, and `sdlc_tasks` across all 8 harnesses.
- **Harness Identity Is Read From the State Directory, Not the Variable Name (`src/mcp/client_detection.js`, `src/mcp/subagent_spawner.js`)**: OMP exports PI's environment verbatim (`PI_SESSION_FILE`, `PI_SESSION_ID`, `PI_CODING_AGENT_DIR`, `PI_GIT_GUARD`) and sets no `OMP_*` marker, so a name-based check reports every OMP session as `pi` and every fresh CLI process dies at `UNSUPPORTED_NATIVE_SPAWN`. Detection therefore inspects the path (`/.omp/` → `omp`, `/.pi/` → `pi`); `ACTIVE_CLIENT`/`KONOHA_CLIENT` still outrank inference. `--execute` resolves the *installed harness binary* rather than the harness's in-session subagent tool, so `--client cli --execute` launches instead of refusing; the `omp` invocation uses `-p --append-system-prompt` because oclif rejects `--agent` with exit 2, and the `task()` directive it tells the model to call carries `solutionSpace` and no `cwd`, because OMP's schema is `{context, tasks:[{name?, agent, task, solutionSpace, …}]}` with `"+": "delete"`. On Windows the resolved `.cmd`/`.bat` shim is launched through `ComSpec /d /s /c` (Node refuses to spawn a shim directly) with the task's newlines flattened to spaces, since cmd.exe treats a newline as a command separator. Guarded by `tests/test_spawn_harness_contracts.js`.
- **Provenance-Aware Native Knowledge Brain & Host Headed Browser QA (`src/memory_brain*.js`, `src/workflow/qa-automation/qa_tools.js`)**: Schema v9 (`45` raw / `33` declared tables; v9 is a data-repair bump, not a table bump — `setupSchema` folds legacy `agy` rows into `antigravity` via `src/db_schema_repairs.js`) stores durable knowledge across `persona`/`project`/`episodic`/`session`/`knowledge` domains with provenance, corrections, supersession, withdrawal, append-only `memory_audit_events`, deterministic `memory_relations`, and conservative dry-run/apply/revert maintenance. Interactive live headed Chromium runs on the host's own Playwright: `qa_e2e_run({ headed: true })` adds `--headed` and `KONOHA_PW_HEADED=1`, which the target config turns into `headless: false`, while `CI=1` drops both so CI stays headless.
- **First-Use Code-Intel Indexing, Async Yield & the Row-Less `@advisor` Charter (`src/code_intel/auto_index.js`, `src/code_intel/search_setup.js`, `src/mcp/memory_subagent_runner.js`, `src/mcp/workflow_sannin.js`)**: `code_search`, `code_symbol`, `code_context`, `code_impact`, and `code_related` index a directory named for the first time instead of answering `root not indexed` — `ensureRootIndexed` runs a lexical-only pass (`embed: false`, `maxFiles: 5000`, `timeoutMs: 15000`), and `code_index` adds vectors later. The async handlers never take that blocking pass: `prepareSearchSetupAsync` and `_resolveAnchorAsync` await `indexRepositoryAsync`, so `tools/list` stays answerable. `code_status` keeps `store.getRoot` and stays read-only — indexing there would resurrect a root `code_remove` just cleared. A row is not proof of an index: `ensureRoot` inserts `stale` with `indexed_at NULL` before the walk, so `isUsableRoot` requires `fresh` or a completed `stale` and retries the rest; a partial completed pass returns `index_incomplete: true`. `@genin`/`@advisor` never trigger that write (`KONOHA_READONLY=1` or the detected agent), concurrent first-use queries share one in-flight pass, and the advisor CLI fallback carries `--execute` so it starts a process instead of printing a directive. `advisor` has no `agents` row by design (the table is the 9-ninja roster), so `_resolveAgentDbMetadata` falls back to `ADVISOR_AGENT_DEFINITION` at the read site rather than seeding it, and `sannin` emits the resolved `spawn_call` / CLI fallback instead of a bare `--idle` directive.
