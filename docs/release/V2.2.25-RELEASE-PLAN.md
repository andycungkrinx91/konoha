# v2.2.25 Release Plan

Plan and gate ledger for the v2.2.25 release. Every gate carries the state it was
last observed in, and the evidence behind that state.

Status vocabulary, used strictly:

- **verified** — the named command or check was run and passed.
- **failed** — run and did not pass.
- **skipped** — deliberately not run; the reason is given.
- **unverified** — not run, or run before later changes; no claim is made.

### #28 — installed mirror

Long-standing: the installer mirrored a hardcoded allowlist of `src/`
subdirectories from v2.2.11 (`src/deploy_installer.js`), with the same shape
earlier in `src/deploy_utils.js` from v2.2.7. It became fatal at v2.2.18 when
`model_router.js` began requiring `../../web/controllers/common`.

The fix walks `src/` with a documented denylist and links every flat entry into
the mirrored tree. Two follow-on defects surfaced in CI and are fixed:

- a Windows runner cannot create file symlinks without Developer Mode, and the
  swap deleted the copy before the replacement existed — the seed lost
  `server.js` and `init` still exited 0 (`6aff39da`);
- the mirror suites asserted link mode on a host that installs in copy mode, so
  they failed on Windows for the correct behaviour (`3614be05`).

Gate: both suites pass, and the golden-seed sentinels survive a refused symlink.

### #29 — workspace boundary

An explicit `KONOHA_ALLOWED_ROOTS` allowlist (path-delimiter separated, mirroring
the existing `KONOHA_ALLOWED_DB_ROOTS`) rather than replacing the boundary with
`WORKSPACE_ROOT`, because one root cannot serve an agent that must read both its
own workspace and the project it was pointed at. The refusal now names the
applied root and both remedies.

A sibling of a named root is still refused, and traversal is refused. Widening
the guard to allow everything was explicitly rejected.

### #30 — Socket license score

Cause: the 2.2.24 `NOTICE` shipped install-graph copyleft SPDX identifiers
(`@img/sharp-*` under LGPL-3.0-or-later, `lightningcss` under MPL-2.0), and
`NOTICE` is in the tarball. The 2.2.25 `NOTICE` carries none of them.

The gate packs the real tarball and fails on any copyleft identifier in shipped
metadata unless it appears on a line that also states a permissive alternative
marked as such. That rule exists because a raw token scan is wrong: `jszip` is
legitimately `MIT OR GPL-3.0-or-later`.

Recorded live score for the published 2.2.24 artefact: **82 overall, License
70**. That artefact cannot be changed retroactively. License should recover
toward 90 only after 2.2.25 is published; **100 is unreachable** while
`@img/sharp-*` and `lightningcss` remain in the optional install graph. No claim
is made that 90 is achieved.

### #31 — macOS leg

`docs/CI.md` documents the dockur/macos container leg and
`scripts/sandbox_preflight.js` reports per-leg availability. The host requirement
that binds is RAM: dockur/macos has a 4 GB floor. `RAM_MINIMUM` is a genuine env
override and this repository does not recommend using it.

macOS is reported as **proxy-verified on Linux, native pending**. It is never
reported as a native pass.

### #34 — skill top-5

`findSkillHybrid` fell back to `SEMANTIC_TOP_K` (10) when no `topK` was passed,
so the hybrid skill path could return twice the top-5 the skill contract
guarantees. It now falls back to `SKILL_TOP_K` (5). `semantic_top_k` is
untouched, because it bounds non-skill semantic search.

Skill resolution through `find_skill` / `get_skill` / `use_skills` resolves to
the top 5 by score, and rank order is authoritative.

### #35 — line ceiling

`src/pi_manager.js` was 712 lines against a 700-line ceiling. The generic
filesystem helpers moved to `src/pi_fs_helpers.js`. One suite also asserted the
old comma form of the Pi tool grants, which the deployer had deliberately
replaced with a YAML sequence because pi-subagents misreads the comma form.

## Deliberate non-claims

- The Socket License category is not claimed to be 90 or 100. Only the 2.2.24
  reading of 70 is recorded, and recovery requires a published 2.2.25.
- macOS native is not claimed. Only the proxy is verified on this host.
- `#25` delivers an audit and a phased plan; no source file was moved, so the
  modularization itself is not claimed.
- Nothing is published, tagged, or released. The branch push is owner-authorized;
  `npm publish` and tags are not.
